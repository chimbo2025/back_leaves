Root cause:
authorize() used $this->user()?->hasPermission('...'), which does not exist on User model. Laravel's authorization uses can('module.action') via Authorizable trait backed by PermissionService.

Invalid calls (4 files):
- app/Http/Requests/StoreDivisionRequest.php: divisions.create
- app/Http/Requests/StoreUnitRequest.php: units.create
- app/Http/Requests/PatchDivisionRequest.php: divisions.update
- app/Http/Requests/PatchUnitRequest.php: units.update

Exact replacement:
$this->user()?->hasPermission('divisions.create') -> $this->user()?->can('divisions.create')
(same for units.create, divisions.update, units.update)

Permission codes used:
divisions.create, divisions.update, units.create, units.update (same as routes middleware).
